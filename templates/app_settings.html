Path passed to -t when testing/applying config — the path as seen from inside the container, which the volume mount may expose at a different location than the Kea Config File path above. Leave blank to use that same path as-is (correct for bare-metal/non-Docker installs).

Kea 3.x installed from ISC's own packages ships no keactrl at all — pick "Control socket" there. It sends config-reload straight to the daemon, needs no external binary, and is the only strategy that reports whether the reload actually succeeded. It requires a unix entry under the daemon's control-sockets.
Minimal Kea Docker images often don't ship /etc/kea/keactrl.conf, which keactrl reload requires — "Docker container SIGHUP" covers those. This is never guessed; pick it explicitly.
